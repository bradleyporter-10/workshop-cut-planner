# Inspection and integration assessment

The existing application is a plain HTML/CSS/classic JavaScript planner, with no frontend framework. Esbuild bundles vendored OpenSKP; Python packages a single HTML file and a GitHub Pages compatible PWA. The Python extractor is a separate CSV utility, not part of browser import. Browser imports must keep working without Python or a server.

OpenSKP's `parseSkp` already returns a root definition, reusable component definitions, nested instances, 13-value placement matrices, vertices, edges, face loops, visibility/layers, and materials. The planner's extraction code composes parent/child matrices and multiplies definition-axis spans by world basis lengths, then sorts L/W/T and groups dimensions and names into quantities. It discards placements and hierarchy after extraction and skips parent-owned geometry. Cut-list rows therefore cannot reconstruct assemblies, but the parsed model can.

Reuse the parser once and feed two consumers: unchanged cut-list extraction and an independent normalized assembly representation. The normalized adapter reuses the planner's existing matrix/reference/visibility helpers. Shared definitions own local face meshes and bounds; instance nodes own path IDs, parent/child relationships, matrices, and modeled measurements. The viewer constructs a matching Three.js group hierarchy with automatic matrix decomposition disabled. Presentation state stays outside source geometry. Milestone 2 adds presentation groups above original instance transforms and applies assembly-space offsets there.

The smallest useful implementation includes a collapsible section, full assembled hierarchy, parsed meshes with explicit box fallbacks, selection, subtree visibility, and camera controls. Three.js and OrbitControls are pinned build dependencies, compiled to a local classic-script bundle and embedded by the existing packaging process. Rendering is lazy, demand-driven, and resources are disposed on model replacement. Shared BufferGeometry reduces repeated geometry allocation; materials remain per instance for selection. The normalizer reports cycles and caps depth at 128 and instances at 20,000. This is an MVP safeguard, not a large-model performance guarantee; synchronous parsing/triangulation may block the browser on large imports.

Risks: reverse-engineered SKP coverage, malformed topology, concave faces/holes, transform conventions, mirrored/nonuniform placements, partial geometry, and browser GPU limits. Keep parser review notes visible and validate against the supplied real model plus isolated transform/topology fixtures. Neutral double-sided faces avoid relying on reconstructed winding for visibility, but do not promise SketchUp's exact visual appearance. Bounding dimensions of irregular or sheared parts require user interpretation.

Parser evaluation:

- **Existing OpenSKP:** already supplies geometry and hierarchy in the browser. No replacement or second parse is needed. Its upstream [documentation](https://iamahsanmehmood.github.io/openskp/docs/) describes geometry and conversion support; implementation targets the vendored API actually inspected here.
- **Skpwright:** its [repository](https://github.com/hew3d/skpwright) describes a Rust SDK, CLI, C ABI and geometry/hierarchy support, with GPL-3.0 licensing. Adding a second native/WASM path offers no demonstrated improvement for this milestone and adds packaging/licensing work.
- **Official SketchUp C SDK:** a native integration would require a separate SDK/toolchain and browser bridge or backend, against the current offline-only architecture. No missing capability in the existing parser currently justifies that integration. No SDK binaries or proprietary service are added.

Three.js [OrbitControls](https://threejs.org/docs/pages/OrbitControls) supplies desktop/touch navigation. [ShapeUtils.triangulateShape](https://threejs.org/docs/pages/ShapeUtils.html) handles planar contours and holes after projection to a dominant plane. Exact material reproduction, nonplanar face repair, source scenes, and geometry healing are outside Milestone 1.

Validation uses `npm test`, `npm run build:distrib`, Python unittest discovery, and `npm run test:pwa:browser`. The real cabinet model currently normalizes into 162 visible instances, with 154 geometry-bearing instance measurements and no normalization review notes. This verifies this fixture, not universal SKP compatibility. Milestone 2 tests now cover explosion percentages, determinism, and full layout reset. Milestone 3 covers fractional annotation formatting and part identification. Individual manual offset resets and exported legends belong with subsequent features.


# Milestone 2: selected-assembly explosion

`explosion.mjs` builds descendant bounds in the selected assembly’s coordinate system by composing local matrices directly. This avoids inverse/decomposition errors for rotated, mirrored, sheared, or scaled placements. Definitions and instance matrices are read only. Immediate child subtrees move as units and repeated definition instances receive independent offsets.

The deterministic greedy algorithm ranks six assembly-axis directions using relative centers and bounding proportions. Boundary panels prefer outward directions; interior parts have a front-direction fallback. Each candidate searches forbidden translation intervals formed by sibling boxes (already placed exploded boxes and not-yet-placed assembled boxes), plus geometry owned by the parent. The chosen offset clears those boxes with a spacing-dependent gap. The completed layout separates all immediate-child bounds at 100%; intermediate positions may intersect and the paths are not disassembly sequences. Bounding-box conservatism can create excess space for irregular or rotated parts. A user-selected axis direction provides a simple fallback. Layout planning is quadratic and capped at 1,000 immediate children; no recursive explosion is implemented.

One active assembly layout is held separately from imported data. Slider changes scale presentation translations, with literal zero vectors at 0%. Changing spacing or direction recomputes the active plan without changing percentage. Clicking Explode switches to the selected assembly at 100%, removing all previous offsets. Reset clears the plan and restores all wrappers. Model replacement also clears the plan. Visibility remains on original instance groups; optional isolation independently filters presentation wrappers and ancestor-owned meshes, preserving user visibility choices. Geometry outside the selected assembly is not a collision obstacle.

Tests check cabinet panel directions, repeated parts, nested groups, rotated descendants, reflected/scaled assembly placement, parent-owned obstacles, coincident components, empty children, all spacing/direction overrides, deterministic results, exact zero vectors, interpolation, reset, and immutable inputs. All 13 nonleaf scopes in the real cabinet fixture are checked for separated children and determinism. Browser tests exercise the actual renderer’s wrapper positions and world matrices at 0%, selection changes, target replacement, spacing/direction/isolation, and reset, alongside existing offline/PWA/direct-file and optimizer checks.


# Milestone 3: labels, part identity, and dimension annotations

`annotations.mjs` supplies pure fractional-inch formatting, local-axis measurement endpoints, an immutable part catalog, and deterministic label placement. Each geometry-bearing instance gets a unique P-number in hierarchy order, including geometry directly owned by a parent assembly. Empty assembly containers do not consume numbers. Qty is always 1 per instance; grouping by name, equal dimensions, or shared definitions would imply manufacturing/material equivalence that the available normalized metadata cannot prove. Numbers survive presentation changes for the same import but are not persistent IDs across SKP edits or reordered hierarchies.

`annotation-layer.mjs` projects local bounds edges through the current instance presentation world matrix and camera into an SVG overlay. L/W/T values use original local spans times the corresponding world basis lengths; translation and camera projection never enter measurement calculations. Four candidate edges per local axis allow exterior dimension placement, including extension lines and outside arrows for short spans. Overall assembled dimensions use the selected assembly’s original descendant bounds in its own coordinates; they include manually hidden parts and exclude internal explosion offsets. This mode is explicitly labeled separately from exploded diagram extents. Source SketchUp dimension entities are not reproduced.

Names, numbers, combined labels, and optional leaders use screen-space text. Annotation rectangles avoid overlaps and viewport clipping; label positions use stable bounded search around projected centers. Text remains upright during orbit/pan/zoom and projection changes. Hidden or isolated-out instances produce no part labels, selected/all-part dimensions, or list rows. This is not depth-aware hidden-surface labeling: unhidden interior parts may be labeled through front surfaces. Long names are truncated only in the viewport, while tree/list text stays complete.

Performance/readability limits are 40 labels and 24 dimensioned part candidates on desktop, 12 labels and 8 dimensioned candidates on narrow viewports; text/edge placement can reduce actual coverage further. The UI reports coverage, and the complete visible-parts list includes offscreen unhidden parts. DOM annotations rebuild on demand with rendering; list rows rebuild only when their identity set or fractional precision changes. No new dependency or runtime network access is added. SVG here is only an annotation overlay and is not offered as a complete vector model export.

Tests cover fraction reduction/carry and precision, local-axis endpoints for rotated/reflected/nonuniform scale, hierarchy numbering and conservative repeated-instance identity, immutability, label modes, bounded collision-free placement, and the real fixture catalog. Browser checks cover all dimension/label modes, thin-part L/W/T, leaders, precision changes without measurement changes, hidden/isolation filtering, complete visible parts, 0% overall measurements, unclipped nonoverlapping phone annotations, and existing cut optimizer/offline workflows.


# Results integration

The user-facing viewer is **Exploded Part Views**. The Parts-list SketchUp importer is its only file source. `results-tabs.mjs` reveals two accessible result tabs only after successful optimization for the current SKP: Cutting layouts is the default, Exploded Part Views is the second panel. Imported geometry stays independent of manufacturing cut-list edits. Imports alone and failed optimizations do not unlock tabs; replacement SKP imports, example/project loads, and Clear reset to cutting layouts and require another successful optimization with a model. Manual/CSV-only projects retain the original cutting-results flow.

The renderer initializes lazily through `setActive` when the second tab is selected. Switching tabs preserves camera, selection, visibility, labels, and explosion state; it redraws/resizes on activation and suspends draws while hidden. Tab buttons support arrow keys and Home/End. The original cutting-results DOM remains intact for printing; print CSS exposes cutting layouts even when its tab is hidden and excludes the tab bar and exploded panel. Browser tests cover the real SKP import/optimization flow, failed-optimization gating, keyboard switching, state preservation, default selection, print, replacement imports, and non-model results.


# Optimization-letter labels

The default Component labels mode is Optimization letter + component name. SKP extraction now returns instance-path-to-group-key metadata alongside its unchanged counts/issues. Import resolves those keys to stable Parts-list row IDs. Expanded optimizer pieces carry `sourcePartId`; after `buildPartLabelMap` assigns letters, the viewer resolves each linked instance to the letter actually used by the current placements. This handles grouped/repeated instances, multi-letter codes, renames, manufacturing size/material edits, and row removal without matching names or inferred dimensional equality. Rebuilt result labels (including unit-driven sorting) resynchronize the viewer. Replacement imports and project clearing discard links and assignments.

The annotation renderer uses the viewer's shared catalog, keeping displayed labels, selected-part information, and visible-parts rows in sync. P-number modes remain available and identify instances independently of cut-plan grouping. Unassigned geometry, including parent-owned assembly geometry omitted from cutting, uses a dash in optimization-label mode, with an explanation in the coverage hint. Original geometry, transforms, and modeled dimensions remain unchanged.


# Milestone 4: manual presentation corrections

`manual-offsets.mjs` converts numeric corrections between normalized imported world-axis frames and presentation wrapper parent coordinates. The selected part's or active assembly's original world basis supplies axis directions; normalizing columns makes UI values physical inches despite reflection/nonuniform scale. Inverse frame conversion preserves the physical correction when the UI changes axes. Sheared frames are supported when invertible; collapsed/nearly parallel axes are rejected. Inputs and conversion outputs must be finite.

Canonical corrections are world-space inch vectors held in per-assembly Maps keyed by stable instance IDs, outside normalized geometry. Any proper descendant of the exploded assembly may receive a correction, including a nested assembly or a part within one. Corrections convert through the original parent's linear world inverse before being added to its wrapper's automatic translation. Ancestor translations naturally carry descendants, while descendants can move independently. Both contributions interpolate with the explosion percentage; literal zero vectors guarantee exact assembled matrices at 0%. No imported transform, dimension, optimization row, or label is modified.

Automatic replanning and scope switching retain custom vectors; maps are cleared on model replacement or full reset. Per-part reset deletes one vector; per-assembly reset deletes only the active map and retains the plan. The existing Reset exploded positions clears all maps and the automatic plan. Reoptimization and tab switches preserve layouts. Numeric inputs require Apply; jog buttons operate on stored corrections with a positive inch step. Manual overlap checking, drag gizmos, undo, and project persistence are not implemented in this milestone. Selected/overall modeled annotations continue to exclude presentation offsets from measurement values.

Pure tests cover axis conversion, physical-inch steps under rotation/reflection/scales/shear, nested parent inheritance, independent instances, interpolation, literal zeros, reset, invalid/singular values, and source immutability. Chrome exercises actual wrapper world matrices against the real cabinet fixture for numeric edits, local-axis jogging, 0/50/100%, axis changes without movement, scoped retention through replanning/switches, invalid inputs, and all reset levels, alongside existing annotations/optimizer/offline checks.

Different modeled sizes/names remain distinct even if linked manufacturing rows share a letter. Unassigned geometry stays per-instance. Group sorting follows letter order A–Z then AA onward, with unassigned rows last. Visibility/isolation drive the table while camera clipping does not, so its totals cover all unhidden instances in scope. Grouping never uses the chosen displayed fraction precision and never changes model or cut-list data. The summary uses the existing responsive table treatment on mobile. Pure/browser tests cover grouping, quantities, dimensions, letter-only labels, filtering, multi-letter assignments, and source immutability.


# Dimensions once per repeated part

The default dimension mode is now Each unique visible part. `dimensionCandidateGroups` groups camera-visible candidates by the summary's assigned letter/name/modeled-size key, or by definition/material/name/modeled size for unassigned geometry. It retains candidate order (selected instance, depth, stable number) for representative choice. The renderer tries alternatives until one receives a dimension, then stops for that group; it never repeats axes or distributes a group's measurements across multiple instances. Desktop/mobile limits now count unique groups, with coverage reporting unique part counts; summary quantities remain complete. # Assembly drawing workspace refinement

User-facing result tabs are Cutting Plan and Assembly Plan. `view-presets.mjs` enumerates stable instance-based banner tabs for root subassemblies and one nested level, disambiguates duplicate names, assigns stable distinct surface shades, and detects geometric front obstructions (including aggregate paired panels) for automatic rear isometric camera selection. Explicit camera presets and a 180° camera turn preserve source/presentation matrices. Each banner scope stores percentage, automatic layout parameters, camera, labels/precision, hidden instances, and style toggles in session memory; existing per-assembly manual maps remain independent. Overview clears only the active presentation plan, not saved manual corrections. New model imports clear all view state.

Explosion options now include logical/even layout and three bounded spread factors. Logical preference scores are geometry/spatial based and resolve collisions along the chosen axis instead of allowing collision cost to choose unrelated directions. Interior horizontal panels prefer forward extraction. Even mode expands child centers proportionally along all assembly axes before the same deterministic collision-interval resolution. Forced directions suppress radial spreading. Completed sibling bounds stay disjoint for the tested logical/even layouts; this is not a disassembly-path solver. Exact zero translation is retained.

`reference-view.mjs` renders assembled geometry in a second on-demand orthographic front renderer. It shares immutable source buffers/edge geometry but owns its materials and camera; automatic/manual offsets and interactive hiding never enter reference transforms. The reference scope is the active subassembly's parent. Muted translucent context surfaces plus outlines retain parent detail; selected subassembly surfaces/edges are gold. Parent front width/height and selected modeled front dimensions provide scale. The main renderer uses stable per-instance tones, flat directional lighting, and shared edge buffers, with raycasting restricted to surface meshes so outlines cannot steal selection. This does not infer inside/outside finishing faces.

Configure controls and hierarchy live in disclosures, leaving the view banner and pull-apart slider visible above the two drawing panels. Reference and main views stack on mobile. Existing optimization letters, grouped summary, deduplicated value-only length/width dimensions, original transforms, offline packaging, and cutting/print behavior are preserved. Unit tests cover camera/front-detection logic, shade stability, logical directions, XYZ spreads/determinism/collisions, and actual SKP assembly scopes; browser tests exercise configuration restoration, camera turning without geometry changes, reference highlighting, style toggles, and existing workflows.


# External callouts and duplicate build views

`callout-layout.mjs` uses padded projected local-bound boxes for every unhidden geometry-bearing instance, including offscreen-center parts that still intersect the viewport. Circular part-marker bodies and dimension text must clear all projected part boxes and previously placed annotation bodies. Dimension measurement segments use slab intersection against those same boxes and move farther outward when obstructed. Candidate positions include anchor rays and perimeter rails; placement is deterministic. Near-plane intersections conservatively reserve the viewport, and impossible annotations are omitted instead of violating clearance. Leader/extension lines still touch geometry by definition. Fit bounds reserve more external space. Default part-letter/number markers are at least 36px circles; long-name modes remain external rectangular labels.

`assemblyViews` now groups subassemblies by shared definition, complete child definition/placement structure, inherited material assignments, rotation-invariant world basis Gram matrix, and handedness. Absolute placement and rigid rotation are excluded. Different names alone cannot establish identity, and different scales/materials/child structure or reflections do not merge. Each group retains a canonical instance and all member IDs, with a Build ×N tab and per-build summary quantity labeling. Tree-triggered explosion of a duplicate resolves to its representative without adding a tab. Original model instances and optimizer quantities are retained.

The reference highlights descendants of every group member, not just the representative. Its displayed parent is the lowest common ancestor of all group instances so repeated nested subassemblies across cabinets are all visible. Current tests on the supplied playroom cabinets.skp find 10 unique build groups from 24 subassembly instances, including four equivalent large cabinets. Unit/browser tests verify rotated-copy grouping, conservative variant separation, common-ancestor selection, circular callout size, geometry/annotation exclusion, safe omission, grouped tabs/counts, duplicate selection, and all-instance reference highlighting.

# Tight fitting and 50% defaults

`camera-fit.mjs` fits source/presentation bound corners in camera coordinates. Orthographic framing fits the limiting horizontal/vertical extent to the available pixel region; perspective framing solves the distance needed for every point at the current FOV and depth. Assembly framing reserves a bubble margin in pixels, while the reference reserves only 10px. World bounding spheres and the union with unused assembled extents no longer inflate the view. Slider changes and actual positive viewport-size changes refit the current assembly while retaining its view direction. Same-size tab activation preserves custom camera settings. New views and direct Explode start at 50%, while saved view percentages and Overview’s assembled 0% remain unchanged. Unit tests cover both camera types, phone/desktop sizes, pixel utilization, margins, frustum depth, and immutable points.


# Planar layouts and assembled-origin guides

Automatic layout detects an axis-aligned thin assembly in its own coordinates (smallest extent ≤25% of the middle extent, with child centers concentrated through thickness). It then locks normal offsets to literal zero and performs axis-normalized expansion within the plane. A common bounded factor solves pairwise planar clearance; normalized distances avoid expanding a long frame's center support past a mating rail. Central anchors are processed first. Coincident/overlapping-center fallbacks use the shortest in-plane clearance ray. Explicit forced directions bypass planar layout, and manual corrections remain user controlled. Nonplanar boxes retain the 3D axis algorithm. Model/world placement rotation does not change the detected local plane.

`origin-guides.mjs` computes original and presented matching trailing-face endpoints for independently moved wrappers. The face anchor is chosen from the movement direction so guides cross the opened joint rather than lying inside a thick rail. It uses immutable imported world matrices and current renderer world matrices, so nested-unit movement and independent manual corrections are represented without duplicating inherited guides on every leaf. Hidden nodes/ancestors and zero offsets produce no guides. The SVG layer projects faint dotted lines plus source crosses behind the label bodies; label leaders remain separate. Fitting includes original guide points when guides are enabled. The toggle is default-on, per-view, and resets with new models; the independent parent reference remains unchanged.

Tests cover a synthetic planar frame with a stationary center support, planar/XYZ spacing, zero normal movement, rotated placements, deterministic nonoverlap, explicit override, guide endpoints/visibility/zero behavior, and the real SKP counter supports/doors/drawer fronts. Chrome validates the real central support, planar movement, dotted guides and their toggle/0% behavior, alongside the existing camera, labels, manufacturing mapping, and offline workflow checks.

# Bottom-up build order

# Installed-app PDF export

Print preparation builds hidden markup while the options dialog remains visible. Native browser printing still uses that markup and calls window.print synchronously on confirmation. The iPhone/iPad installed-app branch instead generates a real application/pdf File before enabling the final button. That tap calls navigator.share with the PDF file; unsupported file sharing falls back to a PDF viewer, and a PDF download remains available. Share cancellation preserves the file and Back to plan restores the original screen.

`printing/pdf.mjs` uses locally bundled jsPDF and AutoTable. It writes selectable text and tables, rasterizes the existing SVG cutting diagrams, and composites assembly images with their SVG callouts. It maintains cutting-layout group/repeat information, assembly dependency order, two-per-page assembly packing, per-build tables, cropped parent references, and parts-list page breaks. Raster canvases are bounded and released one at a time for iPhone memory limits. PDF creation needs no network, browser print service, HTML blob, iframe rendering, or server. Standard PDF font text uses ASCII inch/arrow equivalents; dimension values are unchanged.

The final tap has no awaited work before sharing. Native printing, PDF preparation, and recovery are separate so the browser path is unchanged. Canceling or superseding preparation prevents stale files from becoming available. Blob URLs are released on cleanup. Browser tests verify actual PDF signatures, MIME types, page counts, all three selections, offline generation, final-tap file sharing, canceled sharing, viewer/download fallbacks, and unchanged project data. Native iPhone share-sheet actions still require device verification.

The distribution packager injects manifest tags only into the main head and app-client code only before the final body close. The PDF exporter is embedded into the self-contained distribution. A regression check compiles every generated inline script.
